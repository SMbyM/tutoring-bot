# Бот онлайн-школы репетиторов

Бот для небольшой школы репетиторов (пока в Telegram): запись на пробные и постоянные занятия, окна расписания репетиторов,
перенос и отмена с правилом 12 часов, связка «ученик — родитель — репетитор», напоминания, закрытый канал
с материалами и заглушка оплаты. Ядро не зависит от мессенджера: VK, MAX и веб-кабинет подключаются как новые адаптеры поверх тех же пакетов.

**Стек:** Go 1.24 · PostgreSQL 16 · sqlc + `database/sql` + `lib/pq` · `go-telegram/bot` · Telegram Mini App (vanilla JS) · Docker.
Зависимостей — две, обе без транзитных.

## Что умеет первая версия

| Роль | Возможности |
|---|---|
| **Ученик** | регистрация с согласием на обработку данных; выбор предмета и репетитора; один бесплатный пробный урок у каждого репетитора; отзыв после пробного; закрепление за понравившимся репетитором; постоянное время (каждую неделю) или разовые уроки; перенос и отмена; баланс и оплата; приглашение родителя |
| **Родитель** | привязка нескольких детей (ссылкой или без Telegram у ребёнка — тогда все уведомления приходят родителю); запись, перенос, отмена, оплата за ребёнка; режим «перенос только с моего подтверждения» (по умолчанию) или «свободно»; видит отзывы ребёнка |
| **Репетитор** | недельные окна и отпуска (Mini App или текстом); длительность урока; предметы и «о себе»; список уроков и учеников; после урока отмечает «состоялся / не пришёл / перенесли» |
| **Админ** | приглашает репетиторов; общая цена урока и индивидуальная для репетитора; тарифы (разовый, пакет, абонемент); предметы; отзывы о пробных с кнопкой «сообщить репетитору»; журнал поздних отмен |

Правила, зашитые в домен (`domain/`):

- **12 часов.** Перенос и отмена доступны всегда, но позже чем за 12 часов нужна причина, а урок помечается как поздняя отмена. Видит админ, правило симметрично для репетитора.
- **Родитель приоритетнее.** Изменение от ученика при включённом режиме уходит родителям с кнопками «Разрешить / Отклонить». Решает первый ответивший родитель.
- **Закрытый канал.** Доступ даётся, только если ученику понравился хотя бы один пробный урок, и действует, пока ученик активен. Через 30 дней без занятий и без записей бот исключает ученика из канала. При новой записи доступ возвращается.
- **Отметка урока.** Без ответа репетитора урок через 24 часа считается состоявшимся. Состоявшийся урок списывается с баланса (идемпотентно).
- **Цены.** Цена фиксируется в журнале в момент покупки. Изменение цены не трогает уже купленные пакеты.
- **Напоминания.** Утром в день урока приходят всем, включая родителей, за час — ученику и репетитору. Часовой пояс у каждого свой, повторов нет. Каждый настраивает напоминания сам, первый раз — при регистрации.

## Архитектура

```
                ┌──────────── PostgreSQL ────────────┐
                │  данные школы        outbox        │
                └───▲──────────────▲──────▲──────────┘
                    │ сценарии     │ пишет│ забирает свои записи
        ┌───────────┴───┐   ┌──────┴──────┴─┐   (FOR UPDATE SKIP LOCKED)
        │  cmd/worker   │   │    cmd/tg     │
        │  напоминания, │   │  апдейты TG,  │──► Telegram
        │  отметки,     │   │  Mini App,    │
        │  доступ…      │   │  доставка     │
        └───────────────┘   └───────────────┘
              (позже: cmd/vk, cmd/web — так же поверх ядра)
```

```
cmd/tg                 Telegram-бот + Mini App + доставка outbox в Telegram
cmd/worker             фоновые задачи; в мессенджеры не ходит
domain/                чистые правила: слоты, окна, 12 часов, приоритет родителя, цены, доступ — без БД
store/                 PostgreSQL: репозитории, встроенные миграции, outbox
  queries/             SQL-запросы для sqlc
  db/                  код, сгенерированный sqlc (не править руками: make generate)
core/                  сценарии: запись, перенос, отметки, отзывы, оплата, доступ, напоминания
msg/                   транспортонезависимые сообщения и кнопки
actions/               протокол кнопок: тип на каждое действие, строгий Encode/Decode, лимит 64 байта
ui/                    диалоги и меню для всех ролей (Input → []Message)
outbox/                диспетчер доставки: пачки, ретраи с backoff, постоянные ошибки
transport/telegram/    адаптер: апдейты ↔ ui, выполнение записей outbox
transport/miniapp/     HTTP API + страница Mini App, проверка подписи initData
worker/                цикл фоновых задач
internal/config        переменные окружения (только для бинарников)
```

**Ядро — публичные пакеты, а не `internal/`.** Если понадобится, `domain`, `store`, `core`, `msg`, `ui`, `outbox` переносятся в отдельный модуль `tutoring-core`, и адаптеры подключают его обычной зависимостью с версией. Переписывать при этом ничего не нужно.

**Outbox вместо прямой отправки.** Ядро ничего не отправляет само: оно пишет в таблицу `outbox` «сообщение пользователю», «выдать ссылку в канал», «исключить из канала». Каждый адаптер забирает записи своего мессенджера. Что это даёт:
- воркер не зависит от Telegram и может работать отдельно;
- сообщение пользователю из VK, вызванное действием в Telegram, дойдёт через VK-адаптер;
- при падении сети сообщения не теряются: повтор с backoff 5 с → 1 ч, до 8 попыток;
- если пользователь заблокировал бота, повторов нет;
- лимиты Telegram учитываются через `retry_after`.

Уведомление идёт в мессенджер, где человек был последним (`identities.last_seen_at`). Ребёнку без мессенджера сообщения уходят родителю.

**Идемпотентность фоновых задач.** Каждая задача атомарно «забирает» свою работу (`UPDATE … WHERE NOT …`, уникальные индексы, журнал напоминаний). Поэтому второй экземпляр воркера или бота не создаёт дублей. Это проверяют тесты `TestTwoWorkersNoDuplicates` и `TestParallelDispatchersDeliverOnce`.

**Конкурентная запись.** Бронирование идёт в транзакции под advisory-блокировкой расписания репетитора, а все запросы внутри используют соединение этой транзакции. `TestConcurrentBookingSameSlot` проверяет, что из 10 одновременных записей в одно окно проходит ровно одна. Миграции тоже идут под advisory-блокировкой, так как бот и воркер стартуют одновременно.

## Запуск

```bash
cp .env.example .env    # BOT_TOKEN, ADMIN_TG_IDS, при необходимости CHANNEL_ID и MINIAPP_URL
docker compose up -d --build
```

Поднимаются три контейнера: `db`, `tg` (бот) и `worker`. Миграции применяются при старте. Порт 8080 (Mini App) открыт только на localhost. Наружу его отдаёт HTTPS-прокси, адрес прописывается в `MINIAPP_URL`. Пример для Caddy:

```
bot.example.ru {
    reverse_proxy 127.0.0.1:8080
}
```

**Telegram из РФ.** Варианты: `HTTPS_PROXY=http://…` (стандартный прокси, Go подхватывает сам) или `TELEGRAM_API_URL`, если Bot API доступен через свой туннель.

**VPN-тоннель на уровне системы (WireGuard, AmneziaWG).** Прокси не нужен, но MTU Docker-сети должен совпадать с тоннелем, иначе крупные TLS-пакеты теряются и каждый запрос к Telegram висит около 5 секунд. Узнать MTU: `ip link | grep -A1 wg`, затем указать его в `.env` (`DOCKER_MTU=1280`) и пересоздать сеть: `docker compose down && docker compose up -d`.

**Закрытый канал.** Добавьте бота админом канала с правами «Приглашать пользователей» и «Блокировать». ID канала (`-100…`) укажите в `CHANNEL_ID`.

## Тестовый режим

При `APP_ENV=debug` у админов и репетиторов в меню есть кнопка «🧪 Тест» (или команда `/debug`):

- переключение роли: ученик / родитель / репетитор / админ — чтобы пройти все сценарии с одного аккаунта;
- «Завершить ближайший урок» сдвигает урок в прошлое и сразу запускает вопрос репетитору. Так проверяются отметка, отзыв и доступ в канал без ожидания;
- «Запустить фоновые задачи» — напоминания, продление слотов, синхронизация доступа.

При `APP_ENV=production` всё это отключено: меню скрыто, а действия отклоняются на сервере.

## Тесты

```bash
make test       # юнит-тесты домена (без БД)
make test-db    # всё, включая интеграционные и сквозные сценарии, на PostgreSQL в Docker, с -race
```

- `domain` — слоты, окна, правило 12 часов, приоритет родителя, цены, доступ.
- `core` — полный путь на реальной БД: пробный урок → отметка → отзыв → канал → закрепление → оплата → постоянное время → перенос с подтверждением → поздняя отмена → напоминания → автоотметка; исключение из канала; параллельная запись.
- `ui` — сквозные сценарии «как в Telegram»: пользователи нажимают кнопки, проверяются ответы и уведомления другим. Сюда входят приглашения, роли, права доступа, отсутствие debug в production.
- `outbox` — четыре параллельных диспетчера на 300 сообщений: каждое доставлено ровно один раз, чужой мессенджер не тронут; ретрай и постоянная ошибка.
- `miniapp` — проверка подписи `initData` (подделка, чужой токен, устаревание) и API окон.

CI (GitHub Actions) прогоняет gofmt, vet, тесты с Postgres и `-race`, сборку.

## Доступ к БД: sqlc

Запросы лежат в `store/queries/*.sql`, а sqlc проверяет их против схемы из миграций и генерирует типизированный Go-код в `store/db`. Опечатка в колонке или несовпадение типов ловится при генерации, а не в рантайме. Выборки с соединениями идут через представления (`lesson_details`, `tutor_profiles`, `feedback_details`), поэтому на все запросы к ним приходится одна модель, а не новый тип на каждый. Публичный интерфейс `store` от sqlc не зависит. CI падает, если сгенерированный код разошёлся с запросами (`sqlc diff`).

```bash
make generate   # после правки store/queries/*.sql или миграций
```
